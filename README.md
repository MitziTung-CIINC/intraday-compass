# 分时罗盘

面向 A 股与场内 ETF 持仓用户的开源测试版分时监测工具。输入证券名称、6 位代码、持仓和成本后，可以查看所选证券的公开行情快照、分时状态、手工成交记录与日内做 T 降本统计。

> 只读工具：不连接券商账户，不读取资金，不具备下单能力。公开行情接口没有交易所授权实时等级或可用性承诺，不应替代券商终端。

## Codex Skill

仓库内置可单独安装的 [`intraday-compass` Skill](skills/intraday-compass/SKILL.md)，用于让 Codex 安装、启动、验证和维护本工具，并协助配置 A 股或场内 ETF 追踪、检查行情连接、记录真实成交及分析已闭合的做 T 周期。

在 Codex 中可直接提出：

```text
请从 https://github.com/MitziTung-CIINC/intraday-compass/tree/main/skills/intraday-compass 安装 intraday-compass Skill
```

安装后使用 `$intraday-compass` 调用。Skill 不连接券商或执行交易；不使用 Codex 的用户仍可按下方方式直接运行应用。

## 下载与启动

需要先安装 [Node.js 22 或更高版本](https://nodejs.org/)。直接运行项目不需要 Python、Codex、Tushare 或任何行情 API Key。A 股和场内 ETF 的最新价、分钟 K 线、日 K 与市场指数均由项目自带的东方财富公开行情桥读取；股票还会读取对应行业板块分钟线。

### Windows

1. 在 GitHub 仓库页面点击 **Code → Download ZIP**，解压文件。
2. 双击 `start-local.cmd`。
3. 首次启动会自动安装依赖，完成后访问 <http://localhost:4173/>。

### macOS / Linux

```bash
git clone <repository-url>
cd t0-market-copilot
chmod +x start-local.sh
./start-local.sh
```

也可以手动运行：

```bash
corepack pnpm install
corepack pnpm run local
```

## 添加自己的持仓

首次打开会自动显示“管理监测股票”：

1. 输入证券名称和 6 位 A 股/场内 ETF 代码；系统会识别沪市、深市或北交所。
2. 按需填写行业/备注、持仓股数、今日可卖和持仓成本。
3. 选择 T+1 或 T+0 回转规则。境内股票 ETF 通常为 T+1；只有确认支持当日回转的 ETF 才选择 T+0。
4. 点击“添加并追踪”。左侧列表可继续新增、编辑或删除证券。

持仓配置保存在当前浏览器的 `localStorage`，不会写入 GitHub 仓库。真实成交记录由本机开发数据库保存，也不会上传到其他测试者。

## 同步到 M5Stack StopWatch

刷入配套的“分时罗盘”固件后，在页面右上角打开“行情配置”，找到“StopWatch 硬件同步”：

1. 首次使用时连接手表的 `Compass-xxxx` 热点，访问 `http://192.168.4.1` 填入 2.4 GHz Wi-Fi。
2. 让电脑与手表处于同一局域网，设备地址优先使用 `http://intraday-compass.local`，也可填手表显示的 IP。
3. 填写固件的 `DEVICE_API_KEY`，点击“检测设备”后开启同步。
4. 继续通过“管理持仓”新增或编辑追踪股票；手表会接收最多 8 只持仓、18 根 1 分钟 K 线与当前 B/S 成熟度。

手表上切换持仓后，电脑端会自动切换到同一标的。价格与 K 线遵循 A 股配色：上涨红、下跌绿；信号颜色独立保持 B 点蓝、S 点警示红。

## 主要功能

- 自定义多只 A 股或场内 ETF 持仓，支持新增、编辑、删除和本机保存
- 所选股票 1 秒轮询、Canvas 分时图、均价线、成交量和上证指数背景
- B/S 观察与确认状态机、陈旧行情自动冻结
- 手工记录真实成交、动态持仓成本和完整做 T 周期成功率
- REST、WebSocket 和历史演练三种行情模式
- 桌面与手机响应式界面

## 转债同步雷达

启动应用后访问 <http://localhost:4173/bond-radar>，可以查看全市场可转债与正股的向上联动 Top 10。看板统一以前一交易日收盘价为基准：

- 有效波动包含当日最高/最低与前收之间的跳空位移，避免漏掉高开涨停或低开急跌
- 先过统一硬门槛：正股有效波动不低于 2%，股债均处于日内向上结构，转债对正股上涨的捕获比不低于 0.25
- 专业评分 = 日内向上结构 30% + 有效波动 25% + 活跃度 25% + 联动弹性 20%
- 同步率 = 正向 1 分钟路径相关性 × 70% + 同向分钟占比 × 30%
- 默认剔除转债成交额低于 1000 万元、正股成交额低于 3000 万元或正股带 ST/退市风险标识的组合
- 所有标的一视同仁，不使用名单、人工加分或人工占位；分钟同步率只在通过结构门槛的候选中参与最终排序
- 最多展示 10 组，并保留正股区间位置、转债捕获比、股债收益差和转换溢价率等复核字段

手动生成最新快照：

```bash
corepack pnpm run bond:update
```

最新快照写入 `public/data/bond-radar.json`，同一交易日的归档写入 `data/bond-radar/`。数据采集失败时脚本会以非零状态退出，不会生成伪造行情。

## 行情数据

项目自带一个仅监听本机的 Node.js 行情桥：

```text
http://localhost:8765/quote?symbol={symbol}&market={market}
```

默认全部使用无需密钥的东方财富公开行情接口：快照接口负责每秒更新最新价，`trends2` 负责当日 1 分钟 K 线、市场指数和股票行业板块分钟线，`kline` 负责多日日 K。ETF 使用自身分钟/日 K 和对应市场指数；免费接口没有可靠跟踪指数映射时，该辅助项明确降级，不会伪造数据，也不阻断主模型。

个股/指数分钟线或多日日 K 不完整、数据陈旧、快照与分钟收盘价偏差超限时，页面仍显示最新价，但自动冻结 B/S 判断。行业板块（或 ETF 跟踪指数）分钟线现在仅作辅助显示，缺失时会明确降级但不再阻断提示。官方公开接口是 1 分钟结构数据，不是逐笔行情或交易所直连 Level-1。详细配置、默认阈值和健康检查见 [`docs/hybrid-market-data.md`](docs/hybrid-market-data.md)。公开接口可能限流、延迟、变更或停止服务；页面中的“源站 xx ms”仅表示本次网络请求耗时，不代表行情相对交易所的真实延迟。

信号模型按老师指引把“观察候选”和“可执行确认”分层。量能只汇总已完成的 5 分钟 K 线，以当前同向波段第一根 5 分钟量为 1；价格继续创新高/新低且后续量比不高于默认 `0.70` 时，分别形成 S/B 观察候选（可通过模型上下文收紧到 `0.50`）。成熟度仍按“位置与支撑 25% + 指数/个股环境 20% + 均价线 20% + 5 分钟波段量能 20% + 1/5 分钟九转共振 15%”计算：量能候选 55 分起提示，普通候选 60 分起提示，75 分以上且数据、底仓/回转、方向、差价和时段五个硬门槛全部通过才升级为确认。观察提示不会产生建议下单数量；MACD 和板块只作辅助，不参与主评分。

点击页面右上角“行情配置”，可以替换为自有的 REST 或 WebSocket 行情源。接口需允许浏览器跨域访问，默认 JSON 映射为：

```json
{
  "data": {
    "price": 33.82,
    "previousClose": 33.5,
    "volume": 152600,
    "time": "2026-08-03T10:31:00+08:00",
    "sectorChange": -0.42,
    "indexChange": -0.18,
    "indexLevel": 3560.21
  }
}
```

## 数据与风险边界

- 页面不会发出交易委托；“真实成交”只是用户根据券商成交回报手工录入。
- 场内 ETF 的回转规则由用户设置；工具不会只凭代码判断 T+0 资格，请以券商与基金法律文件为准。
- 股票使用真实行业板块分钟线；ETF 跟踪指数无法从免费接口可靠识别时明确显示辅助数据不可用，不以大盘值伪装跟踪指数。
- 做 T 成功率只统计已经闭合买卖配对的周期，并扣除手工录入的费用。
- 浏览器数据和本地数据库可能因清理站点数据或删除项目目录而丢失。
- 信号算法属于研究辅助，不构成投资建议。
